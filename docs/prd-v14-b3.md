# PRD v1.4 增补设计 · B3 收尾两件（2026-11-26 老板令「赶紧收尾」）

> 令源：老板 2026-11-26「赶紧收尾」。范围：B3 两页——AI 运维建议、多机批量下发（跨机批量命令）。
> 硬约束不变：零服务器、零成本、无中继；平台侧不建任何云服务。
> 流程：本稿过三路独立评审后进编码；评审意见并入本稿后落码。

## 〇、背景与边界

- backlog-v14 记载：B3 两页后端未落码，前端均为 ModulePage 占位。
- 本期为此前 11 项（FR-A11~A21）+ 扩展 9 项（FR-A22~A28）+ 待办总账 A/B/C/D/F 批次之后的最后一块功能账。

## 一、FR-A29 AI 运维建议（中控侧新模块 aiadvice，P2）

### 要点
基于中控已有数据（资源监控时序、告警历史、证书到期、备份策略覆盖、磁盘水位、容器重启次数）做本地规则分析，产出可执行建议清单；不依赖外部 AI 服务。

### 双模式口径（关键裁决点）
- **本地模式（默认，零成本红线）**：规则引擎，纯中控内存计算，无任何外呼。规则集：
  1. CPU/内存 24h 峰值持续超阈值（复用 FR-A23 环形缓冲 + FR-A22 阈值口径）→ 建议扩容或排查进程（附 Top10 进程线索）；
  2. 磁盘水位预测：按近 24h 增长斜率外推，预计 N 天内 >90% → 建议清理（附 logclean 可清容量线索）；
  3. 证书 30 天内到期且自动续期未配置/失败 → 建议处理（复用 FR-A21 巡检结果）；
  4. 节点无备份策略覆盖 → 建议配置（复用 FR-A26）；
  5. 容器 24h 内重启 ≥3 次 → 建议排查（复用 FR-A11 审计）；
  6. 告警历史 7 天内同源告警 ≥5 次 → 建议根治（复用 FR-A19 落账）。
- **外接模式（可选，用户自备）**：用户在设置页自填 OpenAI 兼容端点与 API Key（存中控、落盘 600、审计脱敏），面板点「深度分析」时中控把脱敏摘要（指标数字，不含主机名/IP/密钥）发给用户配置的端点，把返回文本展示为建议。平台侧零成本、零中继（直连用户自填端点）；不填即纯本地模式。
- 外接模式安全口径：出站仅 HTTPS；响应不落盘、不进审计正文（只记调用事实与耗时）；超时 30s；SSRF 防护复用 FR-A20 SsrfGuard（私网段默认拒绝，Admin 可白名单放行——与推送渠道同口径）。

### 验收口径
- 建议结构化：{id, 级别(info/warn/critical), 标题, 依据(引用具体数据点), 建议动作(可带跳转链接)}。
- 本地规则引擎单测覆盖 6 类规则各至少 1 正例 1 反例；数据不足时输出「数据不足」而非臆测。
- 外接模式：Key 不回显（只显示已配置/未配置）；调用进审计（不含 Key 与响应正文）；SsrfGuard 拦截记录留痕。
- RBAC：查看建议 ReadOnly；触发深度分析 Operator 及以上；配置外接端点 Admin。
- 前端：ai 占位页切真——建议卡片列表（级别色标、依据展开、动作跳转），「深度分析」按钮仅外接模式配置后可用。

## 二、FR-A30 多机批量下发（中控侧新模块 batch，P2）

### 要点
对多个在线节点并行下发同一 Agent 操作（白名单操作集），聚合展示逐节点结果；用于批量巡检、批量升级、批量执行运维命令。

### 验收口径
- 操作白名单：仅限既有下发桥已放行的只读与运维操作（sysinfo.overview、sysinfo.metrics_sample、cron.manage list、docker.manage list/镜像清理类、logclean.manage、cert 查询类）；**写操作（启停服务、删数据、改配置）不入白名单**，批量写操作风险不可控，明确不做。
- 节点选择：面板多选在线节点（离线节点置灰）；单次批量 ≤20 节点；逐节点独立 request_id，互不阻塞，单节点超时 30s 不拖垮整批。
- 结果聚合：逐节点 {node_id, 状态(成功/失败/超时), 摘要, 详情(Output)}；部分失败不回滚（各节点独立），聚合页明示成功/失败计数。
- 并发上限：中控侧并发派发 ≤5 节点/批（防下发桥过载），排队执行。
- RBAC：批量下发 Operator 及以上（单节点同操作权限不变，批量不提权——白名单内只读与低危操作）；批量执行记录进审计哈希链（一次批量一条主记录 + 逐节点子记录）。
- 前端：nodes 占位页切真——节点多选表、操作选择、执行进度、逐节点结果展开；无确认弹窗（白名单内无写操作），但执行前展示将影响的节点数。

## 四、明确不做（边界）

- AI 建议：不做本地大模型推理（面板机器跑不动，违反零成本）；不做自动执行建议（只建议不代做，执行仍走各模块既有入口）。
- 批量下发：不做批量写操作、不做跨节点脚本编排（那是 FR-A24/K8s 的活）、不做定时批量（接 FR-A26 计划任务即可）。

## 五、评审修订后的最终验收口径（替代前文冲突条款）

### FR-A29 修订条款
- 外接模式：响应按纯文本渲染，禁止 HTML/Markdown 注入 DOM，URL 不自动转链接，外接模式不生成跳转链接；响应体上限 1MB 流式读取，超限按失败处理；Key 不回显、不进日志/审计/异常堆栈/错误消息，错误只含失败分类（端点不可达/认证失败/超限）；外接调用限频每节点每分钟 ≤1 次；脱敏摘要仅含指标数值与规则标识（不含主机名、IP、节点自定义名称）。
- 磁盘水位规则：metrics_sample 增采 disk_used_kb/disk_total_kb，环形缓冲扩字段；按近 24h 用量斜率外推，预计 N 天内 >90% 触发建议。
- 容器重启规则：docker inspect RestartCount ≥3/24h 触发（经 docker.manage 既有通道），审计只留调用留痕。
- 建议引擎经 IAdviceDataSource 只读门面取数（GetMetrics/GetAlertHistory/GetCertStatus/GetBackupCoverage/GetContainerRestarts），不直接依赖各 Store 内部。
- 建议阈值复用系统设置页（F4）既有告警阈值配置。

### FR-A30 修订条款
- 白名单逐 op 硬编码枚举，仅纯只读：sysinfo.overview、sysinfo.metrics_sample、sysinfo.process_top、cron.manage op=list、docker.manage op=list、docker.manage op=image_list、logclean.manage op=list、logclean.manage op=preview、ssl.manage op=list。白名单外一律拒绝并审计；任何含清理/删除/清空/重启/停止语义的 op 不得进入。
- 服务端逐 op 登记 RBAC 等级，批量端点权限=本批所选 op 等级中最严者；批量入口与单 op 校验双层执行。
- 节点归属服务端二次校验：所选 node_id 必须存在且在线，否则拒绝整批并明示。
- 限频：每用户每分钟 ≤6 批。
- 聚合详情单节点截断 ≤64KB 并标注截断；本期不提供聚合结果导出。
- 批量发起后节点离线：该节点记「超时/离线」，不重试不阻塞整批，不触发节点离线告警（边缘触发口径不受批量影响）。
