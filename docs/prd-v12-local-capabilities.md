# PRD v1.2 增补设计 · 本地化能力补全（2026-11-23 老板令）

> 令源：老板 2026-11-23 晚「全部都要，也不分期，先补全设计，然后按照制度推进」「第三不要哈」。
> 范围：第一档 9 项 + 第二档 3 项（其中镜像拉取并入 Docker 管理，实为 11 个新需求点），第三档（对象存储备份/挂载、自建邮局）明确不做。
> 硬约束不变：零服务器、零成本、无中继；第二档功能仅要求用户侧有网，平台侧不建任何云服务。
> 流程：本设计过三路独立评审后方可进编码（制度令：未过三路独立评审不进编码）。

## 一、新增需求清单（FR-A11 ~ FR-A21）

### FR-A11 Docker 容器与镜像管理（新模块 docker，P0）
- 要点：容器列表（含状态/端口/镜像/资源占用）、启动/停止/重启、容器日志（走 LogStream 回流，复用日志通道）、容器终端（复用 term 通道语义）、镜像列表/拉取/删除；镜像拉取走用户配置的公共源或镜像加速地址（平台侧零投入）。
- 验收口径：所有操作经中控下发桥并审计留痕；容器名/镜像名白名单校验（防命令注入，口径同 shell 白名单）；日志流断连自动重订；拉取进度可查、失败可重试。
- 边界：Compose 编排、应用商店、网络与存储卷管理本期不做（下一版）。

### FR-A12 网站访问统计（新模块 webstats，P1）
- 要点：解析 OpenResty/Nginx 访问日志，按站点出 PV/UV/状态码分布/流量/Top 来源 IP 与 URL，日粒度聚合落盘（dataDir/webstats/），面板出趋势图。
- 验收口径：流式逐行解析（1GB 日志不爆内存，峰值内存 ≤256MB）；日志轮转切割后统计不重不漏（按 inode+偏移断点续读）；统计可按站点/时间范围过滤。

### FR-A13 节点间备份（backup 模块扩展，P1）
- 要点：备份目标新增「其他受控节点」，经中控中转（中控只过账不落盘，流式转发）传输到目标节点 BackupDir；完整性 SHA-256 校验；还原可跨节点拉回。
- 验收口径：传输走自有 gRPC 通道，不经任何第三方；目标节点磁盘不足时拒收并告警；校验失败自动重传一次，再失败告警。

### FR-A14 一键迁移（新模块 migrate，P1）
- 要点：源节点站点+数据库+环境配置打包（复用 backup 全量逻辑），经中控流式转发到目标节点还原；迁移清单（含版本、路径映射）先行预检。
- 验收口径：还原需 confirm=true；还原前目标节点自动快照（同 FR-A9 口径）；防路径穿越；迁移报告列出成功/跳过/失败明细。

### FR-A15 MySQL 主从复制（db 模块扩展，P2）
- 要点：主从关系配置（主库授权、从库 CHANGE MASTER）、复制状态查询（IO/SQL 线程、延迟）、断链重置。
- 验收口径：变更前备份 my.cnf/配置段（时间戳备份，口径同 FR-A2）；复制中断产生面板告警（接 FR-A19）；凭据不落审计日志。

### FR-A16 两步验证（auth 模块扩展，P1）
- 要点：TOTP（RFC 6238）绑定（扫码/密钥）、登录二次校验、恢复码（一次性，10 枚）。
- 验收口径：时钟窗 ±1 个 30s 周期；恢复码用后即焚；绑定需密码复验；全程本地算法，无外部依赖。

### FR-A17 日志清理（新模块 logclean，P2）
- 要点：按路径/大小/年龄规则定时清理，命中文件先压缩归档（保留 N 天）再删，白名单目录绝对保护。
- 验收口径：白名单命中直接拒绝并告警；每次清理留痕（路径/大小/归档位置）；归档过期自动清理。

### FR-A18 负载均衡（新模块 lb，P1）
- 要点：Nginx upstream 管理（节点增删、权重、健康检查、备用节点），生成 site 配置片段。
- 验收口径：配置落盘前 nginx -t 校验，失败不生效并回滚；变更留审计；后端健康状态可在面板查看。

### FR-A19 面板内告警中心（新模块 alerts，P0）
- 要点：统一告警入口——异常登录（复用入侵检测）、磁盘水位、容器异常（FR-A11）、复制中断（FR-A15）、证书到期（FR-A21）、备份失败（FR-A13）等，分级（info/warn/critical），面板列表+未读数。
- 验收口径：告警落盘（dataDir/alerts/）可查可过滤；可标记已读；保留策略默认 90 天；critical 告警触发推送（FR-A20）。

### FR-A20 自定义告警推送（push 页接真，P1）
- 要点：用户自填 webhook URL（钉钉/飞书/企业微信机器人或任意 HTTP 端点），告警触发时 POST JSON 模板；失败重试 3 次指数退避。
- 验收口径：URL 仅支持 http(s)；默认禁内网地址（SSRF 防护，可配置白名单放行）；推送结果留痕；平台侧不建任何推送服务。

### FR-A21 SSL 证书自动续期（ssl 页接真，P2）
- 要点：Let's Encrypt ACME（HTTP-01 挑战）签发与自动续期（到期前 30 天尝试）；已有证书上传管理、到期提醒（接 FR-A19）。
- 验收口径：私钥落盘权限 600；续期失败告警；挑战需站点 80 端口可达（用户侧有网即可，平台零投入）；自签证书路径保留（离线场景）。

## 二、协议与前端影响

- 协议（proto）：新增 docker/webstats/migrate/lb/logclean/alerts 各模块的请求/响应消息，全部走既有 Dispatch 通道（契约 §4 单一正源，白名单同步登记）；容器日志复用 LogStream，容器终端复用 term 通道语义。
- 前端：新增 pg-docker（容器+镜像两签）、pg-webstats 两页；lb/ssl/push/monitor 四页从 mock 切真连；侧边导航「运维」组加 Docker 入口。
- 中控：/api 桥按模块补端点（口径同 /api/nodes/{id}/cmd），全部过鉴权与审计。

## 三、依赖与排期建议（不分期，按依赖排序）

1. FR-A19 告警中心先行（多处依赖其落点）→ 2. FR-A11 Docker（老板点名）→ 3. FR-A12 网站统计 → 4. FR-A13/FR-A14 节点间备份与迁移（共用流式转发底座）→ 5. FR-A18 负载均衡 → 6. FR-A16 两步验证 → 7. FR-A20 推送 → 8. FR-A17 日志清理 → 9. FR-A15 主从 → 10. FR-A21 SSL 续期。

## 四、待评审确认的问题（按「设计不合理即报令」）

1. FR-A13 节点间备份经中控中转：中控只流式转发不落盘，但中控仍承担带宽压力——是否接受？替代方案为节点直连（需打通节点间网络，复杂度高），建议先中转。
2. FR-A20 SSRF 防护默认禁内网：若用户确需推送到内网接收器，白名单由谁配置（建议 Admin 角色面板配置，留审计）。
3. FR-A21 Let's Encrypt 需 80 端口公网可达：纯内网部署场景只能用自签/上传证书，PRD 是否明确标注此限制。
4. FR-A12 统计落盘保留策略：默认保留 180 天聚合数据，是否合适。
